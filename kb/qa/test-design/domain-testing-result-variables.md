## 定義

結果變數（result variable）是程式計算出來的值，不是使用者直接輸入的（例如 K = I × J，或帳戶餘額、扣除各項費用後的實領薪資）。只測輸入變數、從不分析輸出變數本身的定義域，會錯過多數真實軟體的重點——人們買軟體是為了得到結果，不是為了往欄位裡打字。分析結果變數的四步驟：第一步，決定想驗證輸出 Y 的哪些值（如 Y=0、Y=最大可能值）；第二步，找出哪組輸入能算出這個 Y；第三步，找出能產生這個 Y 的完整輸入等價集合（例如 {(I,J) | I×J=0} = {(I,J) | I=0 或 J=0}）；第四步，從這個集合中挑一組或多組代表性輸入實際去測。

## 原理

一般化的寫法是 (y1,...,ym) = f(x1,...,xn)：結果變數本身可以是多維的，而單一輸出值往往對應到一整組不同的輸入組合——測試這個輸出值，意味著從對應的輸入等價集合裡挑選最佳代表，做法跟一般輸入域的領域測試相同，差別只在於是從想觀察的輸出值反推回去，而不是從剛好想到的某個輸入值往前推。

## QA 視角
- 怎麼測：針對每個由程式計算而非使用者直接輸入的欄位（總金額、餘額、手續費、統計數字），先列出想驗證的輸出邊界（0、上限、剛好等於某個門檻值），再反推能產生該輸出的輸入組合，挑選至少一組能讓輸出落在該邊界的輸入去實測，不能只測「輸入欄位本身合不合法」就收工。
- 常見缺陷：只驗證輸入欄位的過濾邏輯（能否送出），完全沒驗證送出後計算出的結果是否正確——只測輸入過濾器而不管後續計算，是業餘測試的典型標誌；結果變數同樣存在邊界（金額上限溢位、除以零、四捨五入產生的進位邊界），沒有反推對應輸入組合去驗證，這類缺陷在正常操作流程裡幾乎不會被無意間發現；多組不同輸入能產生同一個輸出值時，只測了其中最直覺的那一組，沒發現另一組輸入路徑（如透過批次匯入、透過 API 直改、透過退款反向沖銷）算出同樣結果，卻經過完全不同、從未被測過的程式路徑；結果變數本身的型別溢位（如整數相乘超過最大值）容易被排除在測試範圍外，因為它不是使用者直接輸入的欄位。
