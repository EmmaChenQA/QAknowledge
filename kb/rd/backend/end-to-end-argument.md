## 定義
某項功能（去重、完整性校驗、加密）若要真正保證正確，只能由通訊/處理路徑「兩端」的應用邏輯共同確保；中間任何一層（網路層、資料庫層、佇列層）做的同款檢查，都只是錦上添花，不能取代兩端把關。

## 原理
- TCP 序號能擋網路層重複封包，但擋不住使用者手滑連點兩次「送出」；資料庫唯一約束能擋單一事務內重複寫入，但若請求 ID 沒有從前端一路帶到資料庫，照樣會重複入帳。
- 校驗和（乙太網/TLS）能抓網路傳輸損壞，抓不到收發兩端軟體本身的 bug，也抓不到磁碟靜默損壞。
- 中間層加固能提升效能（提早擋掉大部分重複/錯誤），但不能被誤當成唯一防線。

## QA 視角
- 怎麼測：追查「防重複」「防損壞」「防越權」這類保證，到底是在哪一層做的；只驗證中間層（如只驗 API gateway 擋重放）而不驗證最終落地資料，等於沒驗證到端到端。
- 針對去重機制：確認客戶端產生的唯一 ID 是否真的一路傳到 DB 落地層，而不是只在某個中介服務做記憶體去重（重啟即失效）。
- 常見缺陷：只在 API 層做 rate limit/去重，重試風暴繞過中介直接打到下游造成重複扣款；前端沒帶請求 ID，退回去只能靠使用者行為模式猜測是否重複；資料完整性只做傳輸層校驗，沒有應用層/落地後校驗，資料庫層靜默損壞抓不到。
