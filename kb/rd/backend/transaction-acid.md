## 定義
ACID＝原子性（Atomicity，全有或全無）、一致性（Consistency，業務不變式維持成立）、隔離性（Isolation，併發事務互不干擾）、永續性（Durability，提交後不遺失）。

## 原理
- 原子性管的是「一系列寫入中途失敗怎麼辦」，與併發無關；失敗時應整批撤銷，讓應用可以安全重試而不必擔心半套狀態。
- 一致性不是資料庫自動保證的屬性，而是業務不變式（如帳務借貸相抵）；資料庫只能透過約束（唯一鍵、外鍵、check）強制表達得出的那部分，複雜跨欄位/跨表規則仍要靠應用邏輯正確使用事務。
- 隔離性理論上指可序列化，但多數資料庫預設用較弱的隔離級別換效能，實際保證因資料庫、甚至因設定而異。
- 永續性也非絕對：複製到多節點、寫入磁碟、fsync 都可能因斷電、韌體缺陷等失效；沒有任何單一手段是完美保證。
- 單物件寫入（單一鍵值/單一行）通常各資料庫都天然保證原子與隔離；多物件事務（同時改多筆關聯資料，如帳戶餘額＋流水、主表＋二級索引）才需要真正的事務機制介入。

## QA 視角
- 怎麼測：不能只看「回應 200/提交成功」就判定資料正確，必須實際回讀受影響的多筆關聯資料（主表＋明細、餘額＋流水）確認同步；刻意在多步驟操作中途中斷（斷網、強制關閉連線、逾時），驗證是否整批回滾而非留下半套資料。
- 常見缺陷：宣稱「支援事務」但實測發現部分關聯資料更新失敗時仍寫入了另一部分（原子性未落實）；業務規則只寫在應用碼、資料庫沒有對應約束，導致直接寫入 API 或批次腳本繞過驗證造成資料違反不變式；宣稱 ACID 的資料庫實際隔離級別很弱，高併發下出現本文件其他節點描述的髒讀/丟失更新/寫偏差；永續性以為「提交成功=絕對不丟」，實際斷電或複製延遲情境下仍可能丟失最近寫入。
