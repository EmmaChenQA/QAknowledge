## 定義
企業內部資料中心的多數系統不需要拜占庭容錯（BFT），但仍必須對「弱形式的謊言」（硬體損壞、軟體臭蟲、設定錯誤造成的錯誤訊息）加防護，例如封包校驗和、輸入驗證、NTP 多伺服器交叉比對排除離群值。外部/使用者可控輸入（前端、第三方 API）則屬於完全不同的信任等級：這類輸入永遠要當作「可能說謊」處理，不受內部節點誠實假設保護。

## 原理
內部節點誠實假設與外部輸入不可信假設，是兩套完全不同的信任模型：前者假設對方不會蓄意造假、只可能因故障而給出過時或錯誤資訊；後者假設對方可能刻意構造惡意內容繞過檢查。若把使用者輸入驗證邏輯放進「信任內部節點誠實」的同一套機制裡，等於把外部攻擊面誤當內部容錯問題處理，防護力道完全不足。

## QA 視角
- 怎麼測：針對外部/使用者可控輸入（前端表單、第三方 API 回傳、上傳檔案）做邊界值與惡意輸入測試，包含超長字串、特殊字元、型別偽造、重放請求；確認伺服器端是否獨立驗證，而非只信任前端已檢查過。
- 常見缺陷：把使用者輸入的驗證邏輯放在信任「內部節點誠實」的同一套機制裡，被外部惡意輸入繞過；只在前端做輸入驗證，後端 API 直接信任前端傳來的資料而未重新檢查；把資安問題誤判為單純的可用性/容錯故障，用重試或降級掩蓋而非阻擋惡意輸入。
